# 🔍 Отчет: Исправление поиска без учета регистра в системе бронирований

## 🎯 Задача
Реализовать поиск на странице `/admin/bookings` без учета регистра для:
- Номера телефона клиента
- Имени и фамилии клиента  
- Номера автомобиля
- Поиск по нескольким словам через пробел (например, "Тестовый Админ")

## ❌ Проблемы до исправления
1. Поиск работал с учетом регистра (`LIKE` вместо `ILIKE`)
2. Поиск "Тестовый Админ" не находил клиента с именем "Тестовый" и фамилией "Админ"
3. Не работал поиск по комбинации полей имя+фамилия
4. Отсутствовал поиск по номеру автомобиля (`license_plate`)

## ✅ Реализованные исправления

### 1. Замена LIKE на ILIKE для PostgreSQL
**Файл:** `tire-service-master-api/app/controllers/api/v1/bookings_controller.rb`

```ruby
# Было:
"users.first_name LIKE ? OR users.last_name LIKE ? OR users.email LIKE ? OR users.phone LIKE ?"

# Стало:
"users.first_name ILIKE ? OR users.last_name ILIKE ? OR users.email ILIKE ? OR users.phone ILIKE ? OR bookings.license_plate ILIKE ?"
```

### 2. Добавлен поиск по номеру автомобиля
Добавлено поле `bookings.license_plate ILIKE ?` для поиска по номерам автомобилей из гостевых бронирований.

### 3. Интеллектуальный поиск по нескольким словам
Реализована логика разбора поискового запроса на слова:

```ruby
words = params[:query].strip.split(/\s+/)

if words.length >= 2
  # Поиск по комбинации имени и фамилии в разных вариантах:
  # 1. Полная строка в полном имени
  # 2. Имя И фамилия (прямой порядок) 
  # 3. Фамилия И имя (обратный порядок)
  # 4. Обычный поиск по отдельным полям
end
```

### 4. Поддерживаемые варианты поиска
- **"админ"** → найдет "Админ" в имени или фамилии
- **"Тестовый Админ"** → найдет клиента с именем "Тестовый" и фамилией "Админ"  
- **"Админ Тестовый"** → найдет того же клиента (обратный порядок)
- **"+380671234567"** → найдет клиента по номеру телефона
- **"аа1234вв"** → найдет бронирование по номеру автомобиля

  - `users.email`, `users.phone` (через JOIN с client)
  - `bookings.license_plate` (прямое поле)
